# M2 email corpus and event cases

`m2_manifest.json` pins 12 original mail files by upstream path, source version,
SHA-256, and usage conditions. Raw messages are not committed. To obtain local
fixtures, run `python data/fetch_m2_emails.py` explicitly. The fetcher verifies
the pinned archive and every message before writing under ignored `data/emails/`.
Tests and all three tools run offline after the files are present.

The [Phishing Pot collection](https://github.com/rf-peixoto/phishing_pot)
describes honeypot samples and publishes a
[CC BY-NC 4.0 repository license](https://github.com/rf-peixoto/phishing_pot/blob/main/LICENSE).
Individual messages have not been independently adjudicated as phishing; the
manifest records that uncertainty. The
[SpamAssassin public corpus](https://spamassassin.apache.org/old/publiccorpus/readme.html)
calls `hard_ham` non-spam but notes that message copyright remains with original
senders and warns against sending corpus messages into live mail systems. Its
label is not proof that a particular message or link is safe. Raw samples are
kept local for both sources.

`evaluation/cases/m2_cases.json` has two scripted event cases per original
message. `sample_sha256` identifies the unchanged mail bytes. `user_initial_input`,
`fixed_clarification_facts`, and fault injection are invented test conditions,
not observed events. The two prompt injection cases specify a *synthetic body
overlay*; it is added to the decoded mail body when running that scenario and
is absent from the original `.eml`. No case represents a complete real incident.
Development and held-out cases share no mail or source group. The M2 test also
checks cross-split body shingle overlap; this is a screening check, not a claim
that all possible near duplicates in the upstream corpora were identified.

Run offline acceptance tests with:

```sh
PYTHONPATH=src HF_HUB_OFFLINE=1 python -m unittest discover -s tests -p 'test_*.py'
```
